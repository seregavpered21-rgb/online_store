# Инструкция продавца

## Товары и фотографии

1. Войдите под пользователем с ролью `admin` и откройте `/admin`.
2. Создайте товар: заполните название, URL, описание, категорию, цену, вариант, SKU и остаток. Для витрины выберите статус `active`; `draft` и `archived` покупателям не показываются.
3. Откройте `Bearbeiten` у товара для изменения данных. Добавляйте фотографии кнопкой `Bild hochladen` и обязательно указывайте понятный alt-текст.
4. Перед публикацией проверьте цену, остаток, вариант и отображение товара на `/products`.

Не удаляйте уже использованные варианты товара: на них могут ссылаться корзины и оформленные заказы. Вместо этого поставьте остаток `0` или переведите товар в `archived`.

## Обработка заказов

1. Откройте `/admin/orders`. При необходимости скачайте `CSV exportieren` для учёта.
2. Откройте заказ и проверьте состав, сумму, email покупателя и адрес доставки. Для Essen адресом будет договорённость о самовывозе или местной доставке.
3. Добавьте внутреннюю заметку: например, время связи, трек-номер или способ передачи. Она не видна покупателю.
4. После подтверждения заказа смените статус `new` на `confirmed`.
5. После передачи товара смените `confirmed` на `fulfilled`. Если заказ не состоится, выберите `cancelled` до выполнения.

Статусы намеренно нельзя возвращать назад. Если нужно исправить завершённый или отменённый заказ, сохраните причину во внутренней заметке и решите ситуацию с покупателем вручную.

## Перед началом работы

- Проверьте, что `RESEND_API_KEY` и `EMAIL_FROM` настроены в Vercel: без них письма о заказе и смене статуса не отправляются.
- При оплате при получении не ожидайте автоматического подтверждения оплаты: свяжитесь с покупателем и обработайте заказ вручную.
- Не используйте `npm run db:seed` на рабочем каталоге: команда предназначена для пустой демонстрационной базы.

## Регулярная проверка

Каждую неделю просматривайте Dependabot PR в GitHub, проверяйте предупреждения безопасности и перед объединением запускайте:

```powershell
npm test
npm run lint
npm run build
```

Не реже раза в месяц проверяйте в Neon состояние резервного копирования/PITR, возможность восстановить данные и актуальность доступов участников команды.
